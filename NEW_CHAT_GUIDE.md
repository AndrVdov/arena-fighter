# Как начать новый чат по Arena Fighter

Этот файл предназначен для копирования готового первого сообщения в новый чат Codex.

## Что нужно сделать перед началом

1. Откройте в Codex папку проекта `Arena_Fighter`.
2. Выберите подходящий шаблон ниже.
3. Замените текст в квадратных скобках своей задачей.
4. Отправьте сообщение. Не нужно вручную пересказывать всю историю проекта: Codex прочитает проектные документы и Git.

## Универсальный шаблон

```text
Продолжаем работу над проектом Arena Fighter.

Сначала изучи AGENTS.md, README.md, docs/PROJECT_CONTEXT.md, docs/DECISIONS.md и docs/TODO.md. Затем проверь git status, последние коммиты и файлы, относящиеся к задаче. Не изменяй посторонние или незакоммиченные пользовательские изменения.

Задача:
[Подробно опиши, что нужно сделать и какой результат ожидается.]

После реализации проверь изменение в объёме, соответствующем риску, обнови проектную документацию, если она устарела, и сообщи результаты проверок. Не делай commit и push без моего явного указания.
```

## Новая функция

```text
Продолжаем работу над Arena Fighter. Прочитай AGENTS.md и проектную документацию, проверь Git и изучи существующую реализацию связанных систем.

Нужно реализовать новую функцию:
[Название функции и пользовательский сценарий.]

Требования:
- [Первое требование.]
- [Второе требование.]
- [Ограничения или правила баланса.]

Критерии готовности:
- [Как должно выглядеть или работать.]
- [Какие сценарии обязательно проверить.]

Соблюдай существующую архитектуру, чистоту кода и обратную совместимость сохранений. Сначала исследуй связанные файлы, затем реализуй и проверь результат. Commit и push не выполняй без отдельного указания.
```

## Исправление ошибки

```text
Продолжаем работу над Arena Fighter. Прочитай AGENTS.md и проектную документацию, проверь текущее состояние Git.

Ошибка:
[Опиши наблюдаемое поведение.]

Как воспроизвести:
1. [Шаг.]
2. [Шаг.]
3. [Фактический результат.]

Ожидаемое поведение:
[Что должно происходить.]

Сначала найди и объясни корневую причину, затем внеси минимальное исправление без побочных изменений. Проверь исходный сценарий и ближайшие регрессии. Commit и push не выполняй без моего явного указания.
```

## Продолжение незавершённой задачи

```text
Продолжи незавершённую работу над Arena Fighter.

Прочитай AGENTS.md, docs/TODO.md и остальные проектные документы. Проверь git status и diff до любых изменений: существующие незакоммиченные изменения могут быть результатом предыдущего чата, их нельзя удалять или перезаписывать.

Текущая задача:
[Кратко укажи задачу или пункт из docs/TODO.md.]

Определи, что уже сделано, что осталось, и продолжи с текущего состояния. Проверь завершённый результат. Не создавай commit и не выполняй push без моего указания.
```

## Анализ без изменения кода

```text
Изучи Arena Fighter с учётом AGENTS.md и проектной документации.

Нужно проанализировать:
[Архитектуру, механику, ошибку, баланс или конкретный файл.]

Код пока не изменяй. Дай выводы с указанием конкретных файлов, рисков и рекомендуемого порядка действий.
```

## Реализация с коммитом и отправкой на GitHub

```text
Продолжаем работу над Arena Fighter. Прочитай AGENTS.md и проектную документацию, проверь Git и реализуй задачу:

[Описание задачи и критерии готовности.]

После реализации выполни необходимые проверки, обнови документацию, создай отдельный понятный commit и отправь изменения в GitHub. Не включай в commit посторонние изменения. В конце укажи commit, ветку, результаты проверок и ссылку на GitHub или pull request.
```

## Как хорошо описывать задачу

Хорошая постановка содержит:

- что видит или делает игрок;
- текущее и ожидаемое поведение;
- правила механики и ограничения;
- затрагиваемые экраны или системы, если они известны;
- критерии, по которым можно проверить готовность;
- нужно ли делать commit, push или pull request.

Не обязательно угадывать техническую реализацию. Лучше описать желаемый игровой результат, а выбор архитектуры оставить Codex после изучения проекта.

## Что не нужно переносить вручную

Не копируйте длинную переписку из старого чата, если важные решения уже записаны в `docs/DECISIONS.md`, состояние — в `docs/PROJECT_CONTEXT.md`, а незавершённые задачи — в `docs/TODO.md`. Перед закрытием большого рабочего чата попросите Codex актуализировать эти файлы.
